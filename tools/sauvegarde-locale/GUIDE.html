Mise en place de la sauvegarde P1Planner

Deux actions dans Google Cloud Shell, puis un double-clic. Une seule fois. Comptez 10 minutes, plus le temps de la première sauvegarde.

Aucun risque pour la base.

  • La clé créée ici est en lecture seule. Même en cas de bug ou de vol de la clé, Google refuse toute écriture et toute suppression.
  • Le programme de sauvegarde ne contient aucune commande d'écriture ni de suppression sur Firebase.
  • La mise en place n'ajoute qu'un compte de lecture. Rien d'existant n'est modifié.
  • Le script refuse toute autre clé : il faut exactement la clé du compte sauvegarde-locale@p1planner.iam.gserviceaccount.com, par exemple pas une clé administrateur.
  • Aucune clé capable d'écrire n'est créée pour l'instant : elle ne sera créée que le jour où vous devez restaurer.

Mise en place

1. Créer la clé en lecture seule

  1. Ouvrez Google Cloud Shell, avec le compte Google du projet Firebase p1planner. Une console noire s'ouvre en bas de la page, après quelques secondes.
  2. Si une fenêtre de conditions d'utilisation apparaît, acceptez-la.
  3. Copiez la commande ci-dessous, collez-la dans la console noire, puis appuyez sur Entrée.
  4. Si Google demande « Autoriser », cliquez dessus. S'il pose une question terminée par (y/N), tapez y puis Entrée.
  5. Quand le navigateur propose de télécharger cle-lecture-seule.json, acceptez.
( set -e; P=p1planner; C=sauvegarde-locale@$P.iam.gserviceaccount.com; gcloud config set project $P; gcloud iam service-accounts describe $C >/dev/null 2>&1 || { gcloud iam service-accounts create sauvegarde-locale --display-name="Sauvegarde locale (lecture seule)"; sleep 20; }; for R in datastore.viewer storage.objectViewer firebaseauth.viewer firebaserules.viewer; do gcloud projects add-iam-policy-binding $P --member="serviceAccount:$C" --role="roles/$R" --condition=None --format=none; done; gcloud iam service-accounts keys create ~/cle-lecture-seule.json --iam-account=$C; cloudshell download ~/cle-lecture-seule.json; echo; echo "TERMINE : acceptez le telechargement du fichier." )

La commande crée le compte sauvegarde-locale, lui donne 4 droits de lecture (Firestore, Storage, comptes, règles), puis télécharge sa clé. Vous devez voir TERMINE à la fin.

2. Effacer la copie restée chez Google

Une fois le fichier téléchargé, collez cette commande dans la même console, puis appuyez sur Entrée. Vous pouvez ensuite fermer la page.

rm ~/cle-lecture-seule.json && echo "Copie effacee"

3. Double-cliquer sur METTRE-EN-PLACE.cmd

Ce fichier est dans le même dossier que ce guide. Si Windows affiche un avertissement, cliquez sur « Informations complémentaires », puis « Exécuter quand même ». Il fait tout seul :

  1. il range la clé au bon endroit, hors de OneDrive, et la retire de vos Téléchargements ;
  2. il installe les dépendances (une seule fois, internet requis) ;
  3. il vérifie l'accès et mesure la taille ;
  4. il fait la première sauvegarde, de quelques minutes à une heure : gardez le PC branché et ouvert ;
  5. il programme la sauvegarde automatique.

C'est fini quand vous lisez TOUT EST EN PLACE.

Si un message parle de permission, attendez 2 minutes et double-cliquez à nouveau. Si le message dit que le fichier n'est pas la clé attendue, refaites l'étape 1 sans changer la commande.

Ensuite, au quotidien

Vous n'avez rien à faire.

  • La sauvegarde se lance chaque jour à 23 h. Si le PC n'est pas disponible à cette heure, elle se fait dès qu'il l'est (session Windows ouverte, internet) : la dernière sauvegarde doit dater de plus de 20 h.
  • En cas d'échec, un fichier SAUVEGARDE P1PLANNER EN ECHEC.txt apparaît sur votre Bureau.
  • Le résumé de la dernière sauvegarde est dans C:\P1Planner-Sauvegardes\DERNIERE-SAUVEGARDE.txt.
  • Sont gardées : la dernière sauvegarde de chacun des 3 derniers jours, de chacune des 8 dernières semaines et de chacun des 12 derniers mois.

Le jour où il faut restaurer

Cette partie ne sert que si des données ont été perdues. Vous aurez besoin du double-clic sur RESTAURER.cmd, et d'une clé qui a le droit d'écrire, créée seulement ce jour-là.

1. Créer la clé de restauration

Dans Cloud Shell, collez cette commande et acceptez le téléchargement de cle-restauration.json.

( set -e; P=p1planner; C=restauration@$P.iam.gserviceaccount.com; gcloud config set project $P; gcloud iam service-accounts describe $C >/dev/null 2>&1 || { gcloud iam service-accounts create restauration --display-name="Restauration (temporaire)"; sleep 20; }; for R in datastore.user storage.objectAdmin firebaseauth.admin; do gcloud projects add-iam-policy-binding $P --member="serviceAccount:$C" --role="roles/$R" --condition=None --format=none; done; gcloud iam service-accounts keys create ~/cle-restauration.json --iam-account=$C; cloudshell download ~/cle-restauration.json; echo; echo "TERMINE : acceptez le telechargement du fichier." )

Une fois le fichier téléchargé :

rm ~/cle-restauration.json && echo "Copie effacee"

2. Double-cliquer sur ACTIVER-RESTAURATION.cmd

La clé est rangée et l'assistant s'ouvre. Les fois suivantes, RESTAURER.cmd suffit. Choisissez :

  • 1 pour un seul utilisateur : collez son UID, visible dans Firebase, rubrique Authentication (son e-mail marche aussi) ;
  • 2 pour tout le monde, en cas de panne ou de perte massive ;
  • 3 pour voir ce qu'un utilisateur avait, sans rien modifier ;
  • 4 pour annuler une restauration.

L'assistant demande la date de la sauvegarde, montre ce qui manque sans rien écrire, puis demande votre choix. Prenez 1 = remettre seulement ce qui manque. Rien ne s'écrit sans une confirmation tapée.

La restauration remet des données et ne supprime rien. Seul le menu 4 retire ce qu'une restauration avait ajouté, et jamais ce que l'utilisateur a modifié depuis.

3. Quand tout est bon, désactiver cette clé

Attendez quelques jours : le menu 4 a besoin de la clé. Ensuite, dans Cloud Shell, collez cette commande et répondez y. Elle supprime uniquement le compte restauration, et sa clé ne marche plus.

gcloud iam service-accounts delete restauration@p1planner.iam.gserviceaccount.com --project p1planner

À savoir. Une clé de compte de service ne doit jamais être déposée dans le dépôt GitHub (il est public), ni dans OneDrive. L'outil refuse d'ailleurs toute clé rangée dans OneDrive.
